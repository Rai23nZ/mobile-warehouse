# Справочник товаров: поиск артикула по штрихкоду

Файлы этой папки нужны окну «Не подтверждено»: когда кладовщик сканирует
товар, оказавшийся на участке вместо нужного, артикул и наименование
подставляются отсюда.

## Файлы

Один файл на торговую сеть, имя **точно совпадает** со значением на экране
маршрута:

```
data/Sportmaster.csv
data/FunDay.csv
data/O'Stin.csv
data/Demix.csv
```

Загружается только файл выбранной сети. Если файла нет — это не ошибка:
сканирование продолжает работать, но артикул не находится и в отчёт
попадает пометка «ШК нет» вместе с самим штрихкодом.

## Формат

```csv
артикул;наименование;ШК_1;ШК_2;ШК_3
000EHQJ898;Футболка мужская, хлопок 100%;4630123456789;4630123456796;
0062HH1NLR;Куртка зимняя «Аляска»;4610987654321;;
```

- Разделитель определяется автоматически: `;`, `,` или табуляция.
- Кодировка — UTF-8. Excel сохраняет с BOM, это нормально, он снимается сам.
- Наименование можно брать в кавычки, если внутри есть разделитель или
  перевод строки: `"Куртка ""Аляска""; зимняя"`.
- **Колонок со штрихкодами может быть сколько угодно** — не обязательно три.
  Всё, что правее наименования, считается штрихкодами; пустые ячейки
  пропускаются.
- Строка заголовка необязательна. Если её нет, колонки читаются по
  порядку: первая — артикул, вторая — наименование, дальше штрихкоды.
- Артикул должен совпадать с именем файла картинки в `img/<Сеть>/`
  (`000EHQJ898` → `img/FunDay/000EHQJ898.jpg`), иначе на месте фото
  останется белый прямоугольник.

## Обновление базы

Заменить файл и запушить. Больше ничего делать не нужно: приложение
сверяет размер и дату файла со своим разобранным индексом и
переиндексирует базу само, когда файл изменился. Поднимать
`SHELL_VERSION` в `sw.js` для этого **не требуется**.

Разобранный индекс лежит в IndexedDB устройства, поэтому повторные
запуски не тратят время на разбор.

> `FunDay.csv` сейчас содержит несколько демонстрационных строк для
> проверки работы окна. Замените его настоящей базой.

# Ревизия фотографий: `img-rev.json`

Файл собирается скриптом и руками не правится. Он отвечает на один
вопрос: какие снимки на устройстве устарели.

Фото товаров лежат в кэше телефона и намеренно переживают обновления
приложения — их сотни мегабайт, перекачивать всё из-за правки в css
недопустимо. Поэтому **новое** фото объявлять не нужно: его на устройстве
ещё нет, оно скачается само. Объявления требует только **замена** снимка
у артикула, чьё фото уже закэшировано. Замен на порядки меньше: между
двумя июльскими выкладками добавилось 43 277 фотографий и заменилось 9,
поэтому файл остаётся размером в килобайт.

## Как выкладывать фотографии

```
1. скопировать снимки в img/<Сеть>/
2. git add img/ && git commit -m "photo update"
3. python tools/img-rev.py
4. git add data/img-rev.json && git commit -m "img-rev"
```

Шаг 3 обязательно **после** шага 2: скрипт сравнивает записанный в
манифесте коммит с `HEAD`, а незакоммиченные файлы в эту разницу не
попадают — он об этом предупредит и остановится.

Поднимать `SHELL_VERSION` в `sw.js` для обновления фотографий **не
требуется**, и `ASSET_VERSION` в коде больше нет: версия в адресе картинки
не работала (Service Worker сравнивал адреса с `ignoreSearch` и разницы
не видел) и обесценивала кэш всех четырёх сетей разом.

## Что внутри

```json
{
  "commit": "6809cdb7…",          // от него считается следующая разница
  "networks": {
    "FunDay": {
      "rev": 7,                    // номер ревизии фото сети
      "base": 1,                   // самая ранняя ревизия, ещё описанная в changed
      "changed": { "3T0PF5VT45": 7, "4KXP09BYVI": 5 }
    }
  }
}
```

Устройство помнит, на какой ревизии каждой сети оно остановилось.
Совпала — не делается ничего. Выросла — из кэша удаляются только те
артикулы, у которых `changed[артикул] > запомненной ревизии`, и они
перекачиваются при ближайшем показе или прогреве.

История замен подрезается до 50 ревизий; `base` показывает, докуда она
ещё полна. Устройство, отставшее сильнее (телефон пролежал в шкафу
полгода), обновляет фотографии этой сети целиком — то есть перекачивает
только то, что реально понадобится в наряде.

## Массовая перевыгрузка

Если за один раз заменено больше 2000 снимков одной сети, скрипт сам
перестаёт перечислять их поимённо: запись в списке стоит около 24 байт,
и четырнадцать тысяч замен превратились бы в треть мегабайта, которые
едут к устройству при каждом входе на рабочий экран — и так до конца
истории. Вместо списка объявляется ревизия без него (`base` выше `rev`),
и устройство сбрасывает фотографии **этой** сети целиком. Другие сети не
затрагиваются, а перекачивается всё равно только то, что нужно текущему
наряду.

Так, например, вышло 05.08.2026: Sportmaster переиздали целиком, 13 893
замены и 2197 новых снимков.

## Аварийный случай

Переснято столько, что бессмысленно разбирать даже по сетям, — поменяйте
`IMG_CACHE` в `sw.js` (`imgs-v3` → `imgs-v4`). При активации воркера кэш
фотографий удаляется целиком, у всех сетей сразу. Это единственная
кнопка, которая стоит полной перекачки, и нажимать её просто так не надо.
